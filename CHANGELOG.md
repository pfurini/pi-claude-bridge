# Changelog

## UNRELEASED

- **Add: claude-opus-5 model** — Claude Opus 5 is selectable via `/model` as `claude-bridge/claude-opus-5`, and the `opus` shortcut (also AskClaude's default model) now resolves to it. Opus 5 is native 1M: the bridge requests the bare ID with no `[1m]` suffix, and its context does not depend on `provider.plan` or `provider.longContextExtraUsage`. Opus 4.8, 4.7, and 4.6 remain selectable by full ID for pinning and rollback. Fast mode is supported by the model but stays off — the Agent SDK disables it for every SDK consumer unless explicitly opted in, and it has separate billing and prompt-cache behavior, so it needs its own feature.
- **Change: AskClaude effort now resolves per model, and accepts `max`** — AskClaude used a flat table where `xhigh` always meant SDK effort `max`; it now uses the same model-aware `thinkingLevelMap` lookup the provider path already used. On models with a distinct `xhigh` tier (Opus 5, Opus 4.8, Opus 4.7, Sonnet 5, Fable 5) `thinking: "xhigh"` now sends SDK `xhigh` instead of `max` — one tier less thinking than before, and less spend. On models with no separate `xhigh` tier (Opus 4.6, Sonnet 4.6, Haiku 4.5) and for unregistered raw model IDs, `xhigh` still escalates to `max`. `max` is newly accepted by the `thinking` parameter so the top tier can be requested explicitly rather than reached as a side effect of `xhigh`. Independent of Opus 5 and revertible on its own.
- **Add: diagnostic when the installed pi-ai omits a registered model** — the bridge loads into whatever `@earendil-works/pi-ai` the host Pi installed, not the version it pins, and a missing catalog row was silent in both directions: the model vanished from the picker and AskClaude's `opus` default quietly fell through to an older model. Registration now logs the missing IDs and the required pi-ai version once per module load. It never throws; a missing row still degrades rather than breaking startup.
- **Add: isolate Claude Code configuration** — run all bridge-managed Claude Code subprocesses and sessions under `~/.pi/agent/claude` by default, add the validated `provider.claudeConfigDir` override, preserve Pi paths in forwarded AGENTS.md content, keep isolation variables child-local, and add authenticated path-isolation coverage with a fail-fast auth preflight. All three Claude spawn paths (provider, AskClaude, and compaction summaries) now take both the executable and the profile from the same activation-time settings, so a per-project override can no longer split settings and sessions across two profiles. `provider.claudeConfigDir` is validated per source rather than after the merge, so an invalid project override falls back to a valid global profile instead of the built-in default, and its warning prints once instead of on every config reload. The session-seeding profile is a required argument, so a new call site cannot silently seed into the default profile, and the test harness preflights the profile a test actually targets rather than always checking the default.
- **Fix: harden AskClaude SDK policy and diagnostics** — validate configured modes fail-closed, enforce the full-mode lockout on configured defaults, restore partial events and native search tools, disable skills in none mode, correct rate-limit display units, and keep opaque terminal metadata out of retry-classified errors.
- **Tests: isolate SDK inventory and bound RPC shutdown** — prevent user and project settings from contaminating native tool-policy probes and escalate wedged test processes after bounded shutdown waits.
- **Bump: upgrade Claude Agent SDK and aligned peers** — pin Agent SDK `0.3.220` (bundled Claude Code `2.1.220`) and align `@anthropic-ai/sdk` `0.113.0`, MCP SDK `1.29.0`, and Zod `4.4.3`; add the required bypass acknowledgement, typed strict MCP, eager Pi MCP loading, updated AskClaude policies, and terminal `is_error` propagation.
- **Bump: pi-ai >=0.82.1** — required for the `claude-opus-5` catalog entry; Pi dev peers pinned at `0.82.1`. This release also changes the effort behavior of models the bridge already shipped, independent of Opus 5. Sonnet 5 now carries a real `thinkingLevelMap`, so pi `xhigh` sends SDK `xhigh` instead of `max` and the `xhigh`-visibility workaround from 0.6.2 is superseded — the bridge's fallback table is retained only for installs below the peer floor, realigned to the values the catalog now ships. Opus 4.6 and Sonnet 4.6 offer `max` where they previously offered `xhigh` (the SDK effort is `max` either way), and Fable 5, Opus 4.8, and Opus 4.7 gain a real `max` level. Sonnet 4.6's advertised `maxTokens` moves from 64K to 128K; this is inert on the request path because the bridge never forwards `maxTokens` and Claude Code applies its own output cap, so it is visible only in Pi-side computation and `--list-models` output.
- **Fix: gate Fable 5 by subscription eligibility** — hide Fable 5 from Pro users unless Extra Usage is enabled and reject explicit ineligible AskClaude requests before they reach Claude Code; preserve Fable availability on Max.
- **Tests: add Agent SDK upgrade compatibility contracts** — establish the Pi `0.80.3` and Node `>=22.19.0` baseline; cover SDK initialization, MCP tools, AskClaude policies, terminal and abort paths, configuration sources, synthetic sessions, and executable resolution offline; then verify authenticated provider, cache, compaction, native subagent, model aliases, context windows, served-window parity, cross-version transcript/API, and restart-and-rebuild rollback behavior.
- **Remove: drop the RPIV subagent regression fixture** — remove the integration test and agent fixture that depended on a separately cloned, pinned `../pi-subagents` repository.
- **Fix: disable Claude Code auto-memory on the provider and AskClaude paths** — `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` was set only for compaction summaries, so every provider and AskClaude request still carried Claude Code's auto-memory section. That section instructs the model to write memory files with the native `Write` tool, which neither path exposes (the provider sends `tools: []` and AskClaude restricts the inventory), making it unactionable. It was also the largest removable block in the preset prompt: measured on Claude Code `2.1.220`, disabling it halves the legacy-family system prompt (Sonnet 5, Opus 4.7, Opus 4.6, Sonnet 4.6, Haiku 4.5: ~26.8K to ~13.9K chars) and cuts ~2.1K chars from the new family (Fable 5, Opus 5, Opus 4.8). The three spawn paths now share one `CLAUDE_ISOLATION_ENV` constant so they cannot drift apart again, with a test asserting the variable on each. Memories written by earlier sessions are no longer surfaced; nothing on disk is deleted. Because the system prefix changed, existing persisted sessions take a one-time prompt-cache miss on their first request after upgrading.
- **Fix: correct Claude Code prompt statements that are false under this harness** — the `claude_code` preset is generated inside the binary and describes Claude Code's own harness, so two of its claims were wrong for the bridge. With an empty native inventory the legacy-family prompt (Sonnet 5, Opus 4.7, Opus 4.6, Sonnet 4.6, Haiku 4.5) told the model to "prefer dedicated tools over PowerShell when one fits (Read, Edit, Write, Glob, Grep)", naming tools that do not exist here and a shell that is wrong on macOS and Linux; and because `claudeCodeModelId` appends `[1m]` to request 1M context, the prompt reported a model ID (`claude-sonnet-5[1m]`) that is not a valid API model. A `# Harness corrections` block is now appended through the existing systemPrompt seam, naming pi's real `mcp__custom-tools__` surface and the bare model ID. It costs 712 characters at most, and each bullet is emitted only where the defect was measured: the tool disclaimer on the provider path only (AskClaude keeps Claude Code's native tools and gets a narrower shell-only line in `read`/`none` modes), and the model-ID line only when a suffix was actually applied. The corrections are deliberately not gated on `provider.appendSystemPrompt`, which controls forwarding of pi's own content rather than harness fidelity. On the AskClaude path they ride along with the skills block, because sending an append at all is what switches the preset on there — without one that path receives no Claude Code prompt whatsoever, which is now recorded in `diag/SYSTEM-PROMPTS.md`. `AskClaudeQueryOptionsInput.skillsBlock` is renamed `systemPromptAppend` to match what it now carries. The block adds roughly 180 tokens to the cached prefix on every provider request, and existing persisted sessions take a one-time prompt-cache miss on their first request after upgrading (a second one, independent of the auto-memory change above).
- **Fix: send Claude Code's system prompt to AskClaude in full mode** — `buildAskClaudeQueryOptions` left `systemPrompt` undefined when there was nothing to append, which the Agent SDK reads as "no preset" rather than "the default preset". A `full` mode call with no skills block therefore ran with 25 tools (Bash, Write, Edit, Agent and 21 others) against a 136-character system prompt: no `# Environment` block (working directory, platform, OS, shell, git status, model identity) and no `# Executing actions with care`, the reversibility and blast-radius policy. Whether a sub-agent got that framing depended on whether pi's system prompt happened to contain a skills block, which is unrelated to how much damage it can do. `full` mode now always sends the preset; `read` and `none` stay preset-free when there is nothing to append, since `none` has one tool and `read` has a low blast radius. The condition is `mode === "full" || Boolean(append)` rather than a plain mode check because the forwarded skills block is delivered through that same append, and testing the mode alone would silently stop forwarding skills in `read` and `none`. The preset block is prompt-cached with a 1h TTL, so the added cost is a cache write per hour per distinct prefix rather than full input tokens per call. Sending the preset also brought one incoherence: it tells the model to confirm before hard-to-reverse actions, which a delegated sub-agent cannot do (`AskUserQuestion` is blocked, nobody is listening, and `permissionMode` is `bypassPermissions` so nothing gates mechanically). The corrections block now invokes the preset’s own documented override ("if explicitly asked to operate more autonomously, then you may proceed without confirmation, but still attend to the risks and consequences") to release the sub-agent from confirmation while leaving the blast-radius guidance intact. That bullet is not emitted on the provider path, where pi’s TUI does put a user on the other end.
- **Tests: add a system-prompt capture diagnostic** — `diag/system-prompt.mjs` records the system prompt Claude Code assembles per model, for both the plain CLI and the bridge's own `buildProviderQueryOptions`, by pointing `ANTHROPIC_BASE_URL` at a local stub that logs the request and answers 400 (no quota spent). The extracted prompts for all eight registered models are checked in under `diag/system-prompts/`, with the measured record and per-model analysis in `diag/SYSTEM-PROMPTS.md`.

## 0.4.0 — 2026-05-04

- **Fix: Opus 4.7 + xhigh sent wrong effort to SDK** — pi-ai 0.72 ships per-model `thinkingLevelMap` overrides (e.g. `claude-opus-4-7` declares `xhigh→xhigh`, not `xhigh→max`), but our hardcoded `REASONING_TO_EFFORT` table ignored them. Effort lookup now consults `model.thinkingLevelMap` first, falls back to the table for older pi-ai or unmapped levels. Forwarded `thinkingLevelMap` through `buildModels` projection.
- **Fix: zero out model cost in `buildModels`** — per-token pricing in the footer was wrong because models inherited pi-ai's non-zero cost fields, which pi then multiplied by the huge token counts from the SDK. Now explicitly zeroed so pi's footer shows no cost.
- **Use `tools: []` instead of `disallowedTools` blocklist** — switch from blocking specific tools to explicitly passing an empty tools list, preventing any new default tools from silently leaking into bridge sessions.
- **Disable CC-side autocompact (`DISABLE_AUTO_COMPACT=1`)** — pi already owns context management and propagates its own `/compact` to CC. Letting CC autocompact too double-flushed the prompt cache and raced pi's threshold; manual `/compact` in CC is unaffected.
- **Fix: pi `/compact` no longer triggers CC autocompact-thrashing (issue #8)** — pi's compaction shrinks its messages array, but `syncSharedSession`'s REUSE check (`slice(cursor)`) silently returned `[]`, so the bridge kept `--resume`ing the pre-compact CC session JSONL. Over long sessions CC's own autocompact then refilled within 3 turns and tripped its anti-thrashing guard. Now subscribes to pi's `session_compact` event and forces the next sync down the REBUILD path so CC sees the post-compact history. Also subscribes to `session_tree` (branch nav has the same shape).
- **Refactor: split `needsRebuild` into `needsRebuild` + `forceRotate`** — only the abort case needs UUID rotation (to dodge late writes from the dying CC subprocess). Compact/tree now rebuild in place, preserving the sessionId and not leaking orphan JSONL files into `~/.claude/projects/`.
- **Block user-installed MCP servers from leaking into bridge sessions** — pass `--strict-mcp-config` unconditionally and set `ENABLE_CLAUDEAI_MCP_SERVERS=0` in the spawned CC env, suppressing both filesystem (`~/.claude.json`, `.mcp.json`) and claude.ai cloud MCP servers. Override with `provider.strictMcpConfig: false`.
- **Consolidate config** — SDK plumbing (`appendSystemPrompt`, `settingSources`, `strictMcpConfig`) moved from `~/.pi/agent/settings.json` (`claudeAgentSdkProvider` block) to a `provider` block in `~/.pi/agent/claude-bridge.json`. Old location no longer read. Drop deprecated, unsafe `maxHistoryMessages`.
- **Bump deps** — `@anthropic-ai/claude-agent-sdk` → ^0.2.126; migrate to TypeBox 1.x (new import paths per pi-mono 0.69); pi devDeps → ^0.72.1. Extract `registerTool` schemas to const with explicit `<typeof params>` generic to avoid TS2589 deep-instantiation under TypeBox 1.x.
- **Internal: move sources into `src/`** — `index.ts` and the extracted modules now live under `src/`; screenshots under `assets/`. `pi.extensions` and published `files` updated accordingly.

## 0.3.1 — 2026-04-18

- **Fix: empty thinking blocks on Opus 4.7** — Opus 4.7 silently changed default `thinking.display` from `"summarized"` to `"omitted"`, so streams emitted `thinking_start` + `signature_delta` with zero `thinking_delta` events, leaving `ThinkingBlock.thinking == ""`. Now pass `--thinking-display=summarized` via `extraArgs` whenever `effort` is set (both provider and AskClaude paths). Bump `@anthropic-ai/claude-agent-sdk` to ^0.2.111 (required for Opus 4.7 + `--thinking-display` CLI flag). See [anthropics/claude-agent-sdk-python#830](https://github.com/anthropics/claude-agent-sdk-python/pull/830).
- **Fix: `cachePct` debug metric misleading** — denominator was `input + cacheRead`, so once a conversation warmed up (tiny `input`, huge `cacheRead`) every turn rounded to 100% — even turns that rebuilt the cache from scratch. Now `cacheRead / (input + cacheRead + cacheWrite)`, so cache-rebuild turns show a low percentage.
- **Internal: extract pure modules from `index.ts`** — split `models`, `skills`, `session-verify`, `extract-tool-results`, and `query-state` into their own TS files with real unit tests (no more `.js`+`.d.ts` mirror drift). Add `typecheck` script, `typescript` + `tsx` devDeps; test scripts run via `--import tsx`.
